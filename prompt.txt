Build a complete local prototype for an NLP-based E-Commerce Customer Support System.

The real NLP model is not ready yet. Another teammate is training the model separately. For now, create the full frontend and backend using a dummy prediction service. Later, the teammate should only need to replace the dummy prediction logic with the trained model, without changing the frontend, API structure, database, or dashboard.

## Technology Stack

Use:

* Python
* Streamlit for frontend
* FastAPI for backend
* SQLite for database
* Pandas for dashboard data handling
* Requests for communication between Streamlit and FastAPI
* Uvicorn for running FastAPI

Keep the implementation simple, clean, modular, and suitable for an NLP laboratory project.

Do NOT use:

* React
* PostgreSQL
* MongoDB
* RabbitMQ
* Docker
* Authentication
* complicated distributed infrastructure

These may be added later.

# Core System Flow

The system should work like this:

```text
Customer Query
      ↓
Streamlit Customer UI
      ↓
FastAPI Backend
      ↓
model_service.py
      ↓
Prediction:
- subsystem
- issue_type
- priority
      ↓
Create Ticket
      ↓
Store Ticket in SQLite
      ↓
Admin Dashboard
      ↓
Filter tickets by subsystem / issue / priority / status
```

For now, `model_service.py` will contain dummy rule-based predictions.

Later it will be replaced by the actual trained NLP model.

# Important Model Contract

Create this function inside:

```text
backend/model_service.py
```

```python
def predict(query: str) -> dict:
```

It MUST always return exactly this structure:

```python
{
    "subsystem": "Payment",
    "issue_type": "Failed Payment",
    "priority": "High"
}
```

The frontend and backend must depend only on this output format.

Do not put model-specific logic anywhere else.

Add a clear comment:

```python
# TEMPORARY DUMMY MODEL
# Replace only this prediction logic when the trained NLP model is available.
```

Create simple dummy keyword rules.

Examples:

If query contains words related to:

* taka
* payment
* card
* টাকা

return:

```text

Priority: High
```

If query contains:

* delivery

If query contains:


# SQLite Database

Use Python's built-in `sqlite3`.

Database file:

```text
backend/tickets.db
```

Create one table:

```text
tickets
```

Fields:

```text
id INTEGER PRIMARY KEY AUTOINCREMENT
query TEXT NOT NULL
subsystem TEXT NOT NULL
issue_type TEXT NOT NULL
priority TEXT NOT NULL
status TEXT NOT NULL DEFAULT 'Pending'
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```

Implement functions inside:

```text
backend/database.py
```

Required functions:

```python
init_db()
create_ticket()
get_all_tickets()
update_ticket_status()
```

Use parameterized SQL queries.

Set:

```python
conn.row_factory = sqlite3.Row
```

so database rows can easily be converted into dictionaries.

# Simple Routing Logic

Do NOT create separate physical queues.

Use the `subsystem` field as simple routing.

For example:

```text
Payment ticket
→ stored with subsystem = "Payment"

Delivery ticket
→ stored with subsystem = "Delivery"

Product ticket
→ stored with subsystem = "Product"
```

The admin dashboard will treat filtered subsystem tickets as subsystem queues.

Conceptually:

```text
SQLite tickets table
        │
        ├── Payment Queue
        ├── Delivery Queue
        ├── Product Queue
        ├── Refund Queue
        ├── Account Queue
        └── Technical Support Queue
```

These are logical queues created by filtering the same SQLite table.

---

## POST /tickets

Input:

```json
{
    "query": "amar taka kete gese but order confirm hoy nai"
}
```

Process:

```text
Receive query
→ validate query is not empty
→ call predict(query)
→ get subsystem, issue_type, priority
→ create ticket
→ save to SQLite
→ return complete saved ticket
```

Example output:

```json
{
    "id": 1,
    "query": "amar taka kete gese but order confirm hoy nai",
    "subsystem": "Payment",
    "issue_type": "Failed Payment",
    "priority": "High",
    "status": "Pending",
    "created_at": "2026-09-18 01:20:00"
}
```

Use a Pydantic request model.

Reject empty queries with HTTP 400.

---

## GET /tickets

Return all tickets ordered newest first.

---

## PATCH /tickets/{ticket_id}/status

Input:

```json
{
    "status": "Resolved"
}
```

Update ticket status.

Allowed statuses for this prototype:

```text
Pending
Resolved
```

Return a success response.
